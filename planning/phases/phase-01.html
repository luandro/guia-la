Phase 01 — Legacy extraction and preservation audit

Produce a read-only, source-linked inventory of everything in luandro/cotiju-app worth keeping — entities, data, media, business rules, tests — with a rights and privacy verdict per item.

Status: draftMedium (privacy)Learndepends on: 00

Phase 01 is a read-only audit plus sanitized extraction of the legacy Cotiju application. It does not migrate anything, does not fix the legacy app, and does not import real content into guia.la — real-data import is Phase 09, and only for items this phase has cleared.

The planning pass already produced a first audit (research/legacy-cotiju-audit.md, baseline commit c0c9907, 2026-11-21). This phase deepens it into per-item verdicts, obtains real row counts through an owner-run export, and turns reusable knowledge into synthetic fixtures and test scenarios for phases 02–08.

Risk

The single worst outcome of this phase is a privacy leak into the

new repository: a phone number, profile row or user photo copied "because it was useful". Default verdict for anything personal is do not migrate (review §6); re-collection with consent happens in Phase 09.

Phase identity

  • Number: 01 — second phase; runs after 00 and may run

in parallel with the 02 spike.

  • Objective: classify every legacy entity, data source, media asset,

business rule and test scenario into concept / code / data / fixture / reject, with provenance, freshness and rights recorded; obtain an owner-run read-only data export; ship synthetic fixtures guia.la can legally use.

  • Prerequisites: Phase 00's approval list and evidence template; confirmed

read-only access to luandro/cotiju-app; owner awareness of D-12 (leaked keys in legacy bundles).

  • Dependencies: 00.

Why this stage exists

The master plan (§02 legacy lessons) makes extraction a dedicated early phase because the legacy app mixes three things that must be separated before guia.la's schema exists: genuine domain knowledge (boat schedules with validity periods, tide data with sources, place coordinates), disposable accidental complexity (a 4,681-line baseline migration, 146 RLS policies, 59 SQL functions — legacy audit §4), and unowned liabilities (2025-only tide fallback data, user photos with no consent record, API keys bundled into public JavaScript).

Designing Phase 07's schema without this audit would repeat PR #39 — the legacy repo's closed, unmerged D1 migration that ported all 24 tables and ballooned to +99k lines before being abandoned (legacy audit, PR 39). The audit is the countermeasure: minimum viable v2 models justified row by row.

It is also where guia.la's trust model starts. Legacy issues #62, #64 and #70 (legacy audit §8-9) all reduce to "data without provenance or freshness is worse than no data". The extraction matrix introduces the columns — source, verified date, rights — that Phase 07's schema and Phase 09's editorial workflow inherit.

Architecture choices and guardrails

  • Location of outputs (proposed, in the guia-la repo):

docs/legacy/extraction-matrix.md, docs/legacy/rights-matrix.md, docs/legacy/scenario-port-list.md, docs/legacy/export-runbook.md, docs/legacy/migration-plan.md, and fixtures under packages/fixtures/cotijuba/ and packages/fixtures/serra/ (consumed by Phase 02).

  • Verdict vocabulary (fixed; exactly one per row):
concept   design knowledge only; nothing copied
code      legacy source adapted with attribution into guia.la (rare)
data      real content may migrate in Phase 09, pending rights + freshness
fixture   becomes synthetic test data now (shapes real, values fake)
reject    neither ported nor migrated; reason recorded
  • Fixture shape contract (illustrative):
// illustrative — final types land in packages/core in Phase 02
type FixturePlace = {
  id: string;            // synthetic, e.g. "fx-cotijuba-001"
  slug: string;
  name: string;          // invented or public-knowledge names only
  category: "beach" | "restaurant" | "stay" | "waterfall" | "trail";
  location: { lat: number; lng: number };  // plausible, not exact personal data
  source: "synthetic";   // fixtures are never real rows
};
  • Forbidden: any write to luandro/cotiju-app (issues/comments included,

beyond what the owner posts); agents holding or transmitting the Supabase service key or legacy .env values; copying personal data or user media into any repo or chat; running the legacy app against production; publishing export contents; porting the 24-table PR #39 schema wholesale (review §6).

  • Security/privacy implications: the export contains personal data by

construction (profiles, phones). It stays in owner-controlled encrypted storage; the only values that enter the guia-la repo are aggregate counts and explicitly public fields. Fixtures pass an automated privacy scan (below) before merge.

  • Acceptable alternatives: skip the audit and design schema fresh

(rejected — loses verified domain rules and the URL map); full data migration now (rejected — rights unknown, and Phase 09 exists for this); using legacy test code directly (rejected — it encodes 455 type errors' worth of drift; scenarios port instead).

Visual and functional QA

No UI is produced. The inspectable surfaces are the matrix documents and the fixtures as data files.

  • Human journey: open extraction-matrix.md, pick three random rows, and

for each click through to the cited legacy file:line or issue — every verdict must be traceable. Open the rights matrix and mark each row keep/ask/drop as the rights ruling (this is the D-11 input). Confirm the backup confirmation line exists and predates any export artifact.

  • Agent journey: from the matrix alone, generate one fixture set and

answer: which verdicts did you use, and what did you refuse to copy? The refusal list must match the privacy classification.

  • Spot-check journey: trace one real concept end to end — boat schedule

validity (#64) → scenario text → planned test location in Phase 08 — and confirm nothing in the chain invents legacy behavior.

  • Platform matrix: not applicable (documents and JSON only).
  • Error states: audit refresh finds the repo has moved materially →

re-baseline the matrix against new HEAD and note deltas rather than silently mixing commits; export returns errors or zero rows → stop, record, escalate to owner — never retry with elevated credentials.

Acceptance gate

Gate

Phase 01 passes when every legacy item has a traceable verdict,

fixtures contain no personal data, and the owner has personally confirmed the backup and (if run) executed the export. Nothing in this phase wrote to the legacy repo or database — that is a gate condition, not a hope.

  • All 23 tables, 3 storage buckets and static data files have verdict rows; none blank
  • Every verdict row links to its source (file:line, issue, or runbook output)
  • Backup confirmation recorded before any export timestamp; export (if run) executed by the owner only
  • Privacy scan passes on committed fixtures; its deliberate-failure demo is evidenced in a PR
  • Rights matrix delivered with unknowns explicitly marked unknown — no invented licences
  • Migration-plan draft states its Phase 09 gate; no real content imported anywhere
  • Zero writes to luandro/cotiju-app (PR history and issue history show none from agents)

Blocks progression if: fixtures leak personal data (blocks Phase 02's walking skeleton until regenerated); the backup gate is unconfirmed (blocks the export and therefore real row counts); rights are recorded as known when they are not (blocks D-11 and Phase 09 planning).

You are the Phase 01 audit agent for guia.la: you produce a read-only,
source-linked inventory of everything in `luandro/cotiju-app` worth keeping,

## Stop and ask when…

- The backup confirmation is missing or ambiguous — do not proceed to
  export-adjacent work.
- Anything in the legacy data looks personal and a human has not ruled on it.

  real content now — both are forbidden; Phase 09 exists for real data.
