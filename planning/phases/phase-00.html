Phase 00 — Charter, working agreement and decision baseline

Stand up the docs-only guia-la repository — AGENTS.md, SPEC.md, ADRs, evidence rules — so every later phase inherits one set of permissions, names and records.

Status: draftLow (coordination)Govern

Phase 00 converts this planning packet into the future repository's operating system. It writes documents only — no application code, no scaffolding, no CI credentials (except the standing D-14 RevEngine CLAUDE_CODE_OAUTH_TOKEN review workflow), no deploys. Everything later phases are allowed or forbidden to do is decided here and recorded where an agent can read it in one place.

Note

Nothing in this phase authorizes implementation. The packet

(index) must be approved first; this playbook is the first execution step after approval, per review §10.

Phase identity

  • Number: 00 — the first phase; nothing precedes it.
  • Objective: create the guia-la repository (proposed name, see D-01) containing the agent working agreement, platform spec, decision records, evidence rules and the security/privacy/spend baseline, with every open decision recorded at its honest status.
  • Prerequisites: this planning packet is approved by the owner; the review's proposals (review §2, §8 roadmap edits) are understood as proposals, not approved facts.
  • Dependencies: none. Phases 01 and the 02 spike may start as soon as this phase's decisions are recorded.

Why this stage exists

The legacy Cotiju app failed operationally as much as technically: 455 hidden tsc errors because nothing enforced typechecking (legacy audit, issue #69), two live deploy targets so nobody knew which commit served production (incident #63), and data whose freshness nobody owned (review R1). Those are charter failures, not code failures — the rewrite inherits them unless the rules are written down first.

This phase also exists to make decisions cheap to change now and expensive to change later: bundle IDs and store names are effectively permanent after first release (decisions D-01), so candidate names are recorded with an ownership checklist before any identifier is committed to code in Phase 02.

Finally, an agent-led team needs one evidence standard. The master plan (section 07) requires every PR to carry inspectable evidence; this phase defines the template so phases 01–10 all produce the same shape of record, and traceability.md can link against a stable format.

Automated verification

All commands are proposed — none has run; expected outputs are stated so a failing run is recognizable. They belong in a tiny scripts/check-docs.sh added by PR 00-6.

# proposed — structure check: fails if any expected document is missing
for f in AGENTS.md SPEC.md docs/roadmap.md docs/glossary.md \
         docs/evidence/PR-EVIDENCE.md docs/security/APPROVAL-LIST.md \
         .github/PULL_REQUEST_TEMPLATE.md; do
  test -f "$f" || { echo "missing $f"; exit 1; }
done
# proposed — ADR status lint. Expected: no output (pass).
# Matches the template's "- **Status:** …" line form as well as a plain
# "Status:" line; a trailing note after an em dash is allowed because
# statuses are copied verbatim (e.g. "proposed — blocked on S1").
# Deliberate-failure demonstration: add a draft ADR with
# "- **Status:** decided" and confirm this command prints it and exits non-zero.
grep -E '^(Status: |- \*\*Status:\*\*)' docs/adr/*.md \
  | grep -vE 'Status:\*{0,2} ?(proposed|validated|approved|rejected)( —.*)?$' && exit 1
# proposed — decision consistency: every D-xx in the packet's decisions.md
# has an ADR carrying that id in its filename or front matter/body.
# Unanchored on both sides, so a heading-format drift in decisions.md cannot
# silently empty the list and turn the check into a vacuous pass.
# Expected: no output (pass).
ids=$(grep -oE 'D-[0-9]{2}' ../planning/decisions.md 2>/dev/null | sort -u)
test -n "$ids" || { echo "no D-xx parsed from ../planning/decisions.md"; exit 1; }
missing=$(comm -23 <(printf '%s\n' "$ids") \
  <({ ls docs/adr/; cat docs/adr/*.md; } | grep -oE 'D-[0-9]{2}' | sort -u))
test -z "$missing" || { echo "ADR missing for: $(echo $missing)"; exit 1; }

Negative test worth keeping: the status lint above is itself the deliberate-failure demo — it must catch a bad status, or it is decorative.

# Phase 00 agent execution brief — charter, working agreement, decision baseline

NOT FOR EXECUTION — this is a planning artifact. Do not act on it until the
owner has approved the planning packet (`planning/index.html`). It is the
execution prompt embedded in `planning/phases/phase-00.html`.

## Role

You are the Phase 00 agent for guia.la: you create the docs-only `guia-la`
repository — working agreement, spec, ADRs, evidence rules — and nothing else.
You are a careful technical writer with merge discipline, not an implementer.

## Hard constraints (global essentials)

- No writes to any production data or legacy system; this phase touches no
  database, no legacy repo, no deployment.
- No secrets anywhere: no keys, tokens or `.env` values in files, PR bodies
  or evidence.
- No store publication, DNS changes or spending without explicit human
  approval — and none is needed or expected in this phase.
- Evidence over claims: never write that a check "passed" unless its output
  is quoted in the PR; planning language ("expected", "must") stays planning
  language.
- Small PRs: one document or one bounded change per PR, per the task table.

## Canonical docs to read first (relative to the future repo root)

1. `planning/phases/phase-00.html` — the full playbook for this phase.
2. `planning/decisions.md` — statuses D-00..D-14; copy verbatim, never upgrade.
3. `planning/review.md` — proposals (R1–R16, §8) are proposals.
4. `planning/src/index.md` and `planning/traceability.md` — packet context.
5. Master plan and handoff (current repo): `docs/guia-la-master-plan.html`,
   `docs/guia-la-agent-handoff.md`.

## Acceptance criteria

- `scripts/check-docs.sh` exits 0 on a clean clone (first real run quoted).
- ADR-status deliberate-failure demo evidenced once (bad status caught).
- A fresh agent cold-reads AGENTS.md + roadmap and correctly states the next
  task and its PR unit — quoted in PR evidence.
- Owner approvals recorded for AGENTS.md, SPEC.md, APPROVAL-LIST.md.
- Repo contains no application code; no decision status upgraded.

## PR evidence package (every PR)

1. Summary: what and why, one paragraph.
2. Linked phase task: "PR 00-N — <task>".
3. Commands run with verbatim output excerpts (e.g. check-docs.sh run).
4. Screenshots/recordings/stories: none expected this phase — say so rather
   than fabricating.
5. Risks: what could still be wrong.
6. Docs updated: list.
7. Next unblocked task: name it.

## Stop and ask when…

- Any decision needs a status change you did not observe the owner make.
- Naming checks reveal `guia.la` / `guia-la` is unavailable or already used.
- Anything tempts you toward application code, CI credentials, store or
  domain accounts, or publishing the repo — all human decisions.
- The owner's accept/reject responses on PR 00-9 conflict with each other.
