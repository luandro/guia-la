# Brief: planning HTML generator (for glm)

Goal: a dependency-free generator that turns Markdown sources into self-contained, reviewable HTML playbooks for the guia.la planning packet.

Context: repo root is this worktree. The visual reference is `docs/guia-la-master-plan.html` (read its <style> block: warm off-white --bg #f7f5ef, deep teal --deep #0c3438 / --sea #155c60, lime accent --lime #d3f08e, system fonts, mono labels, left sticky rail nav, dark hero). Match that design language; do not copy its content. Avoid "AI dashboard" clutter.

Build exactly:
1. `planning/tools/build.py` — Python 3 stdlib only (no pip installs, no network). Usage: `python3 -I planning/tools/build.py` from repo root. Reads:
   - `planning/src/phases/phase-XX.md` (XX = 00..10). Each starts with a metadata block between `---` lines of simple `key: value` pairs: id, title, short, tag, status, complexity, depends (comma list of phase ids), inspect (one line), exit (one line). Body uses `## ` H2 sections (normally 12).
   - `planning/src/index.md` (same metadata block format with title; body markdown) for the index intro.
   - `planning/prompts/phase-XX-agent.md` (raw markdown, embedded verbatim).
   Writes: `planning/phases/phase-XX.html` and `planning/index.html`.
2. A small Markdown renderer inside build.py supporting: H2-H4 (with slug ids), paragraphs, unordered and ordered lists (with one level of nesting by 2+ space indent), GFM pipe tables (wrapped in a horizontally scrollable div), fenced code blocks (escaped, language class), blockquotes, callouts written `> [!GATE] text`, `> [!RISK]`, `> [!DECISION]`, `> [!NOTE]` rendered as styled asides with a text label (not color alone), inline code, **bold**, *italic*, [links](url), and `- [ ]` / `- [x]` checkboxes rendered as disabled checkboxes. HTML-escape all text. Unknown syntax degrades to paragraphs.
3. Phase page layout: left rail with brand "guia.la", link back to ../index.html, auto table of contents from H2s, prev/next phase links; hero with phase number, title, short objective, status/complexity/tag pills, depends-on links; main content; a final "Agent execution prompt" section that shows the relative path `../prompts/phase-XX-agent.md` as a link plus the prompt contents in a <pre> inside <details> (open by default), and a Copy button that works with JS and is harmless without it.
4. Index page: hero from index.md, then a phase table/grid (number, title, tag, depends-on, what reviewers can inspect, exit gate, status) linking to phases/phase-XX.html, a simple dependency strip/graph rendered in pure HTML/CSS (no external libs), then index.md body (open decisions etc). Links to ../planning files like review.md, decisions.md, traceability.md must be relative and work from file://.
5. Requirements for all HTML: single file, embedded CSS (one shared CSS string in build.py), no external scripts/fonts/CDNs, keyboard accessible (skip link, focus-visible styles, real <nav>, <main>, landmarks), responsive (rail collapses above content under ~860px), print stylesheet (hide rail/buttons, expand details, show link URLs for external links), lang="en", meaningful <title>, color contrast AA.
6. Create two tiny sample sources so the build runs: `planning/src/index.md` and `planning/src/phases/phase-00.md` with placeholder text clearly marked "PLACEHOLDER — replaced by orchestrator" exercising every supported syntax, plus `planning/prompts/phase-00-agent.md` placeholder. Missing phase sources must be skipped with a warning, not crash; the index still lists phases that exist.
7. `planning/tools/check.py` (stdlib): validates every generated HTML: parses with html.parser without errors, every relative href/src resolves to an existing file, no http(s) <script>/<link>/<img> src, each phase page has the 12 required H2s (list them as a constant: "Phase identity","Why this stage exists","Inputs and source references","Task breakdown","Architecture choices and guardrails","Deliverables","Visual and functional QA","Automated verification","Acceptance gate","Risks, rollback and handoff","Next phase handoff","Agent execution prompt" — the last may be generated by the template), and exits non-zero with a clear list of problems.

Forbidden: editing anything outside `planning/`; adding dependencies; network calls; git commits.
Done when: `python3 -I planning/tools/build.py && python3 -I planning/tools/check.py` both exit 0 on the samples, and you report the commands you ran with their output. Keep build.py readable (< ~700 lines).
