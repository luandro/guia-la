# Roadmap — phases 00–10

This file is a mirror. The planning packet is the source of truth. Titles
and exit gates are copied from each playbook's front matter
(`planning/src/phases/phase-NN.md`). If this table and a playbook disagree,
the playbook wins; fix this file.

Decision statuses live in [planning/decisions.md](../planning/decisions.md)
and are never changed here.

| Phase | Title | Objective | Exit gate | Playbook |
|---|---|---|---|---|
| 00 | Charter, working agreement and decision baseline | Stand up the docs-only guia-la repository — AGENTS.md, SPEC.md, ADRs, evidence rules — so every later phase inherits one set of permissions, names and records. | Owner approves the docs-only repo and D-01/D-03/D-06/D-08/D-09 responses; no application code exists in the repository | [00](../planning/phases/phase-00.html) |
| 01 | Legacy extraction and preservation audit | Produce a read-only, source-linked inventory of everything in luandro/cotiju-app worth keeping — entities, data, media, business rules, tests — with a rights and privacy verdict per item. | Every legacy entity and asset class has a recorded verdict (concept, code, data, fixture, reject); owner has confirmed a backup before any export; no write ever touched the legacy repo or database | [01](../planning/phases/phase-01.html) |
| 02 | Bootstrap Expo universal monorepo with a walking skeleton | Create the pinned SDK 58 Expo Router workspace that builds one reference Places journey from fixtures on web, Android and iOS — and prove raw-HTML SEO on the static web export (spike S1). | Clean clone reproduces the web export with raw-HTML OG assertions passing for list and detail routes; native boot evidenced or recorded as credential-blocked with exact setup steps; S1 result recorded against D-03 | [02](../planning/phases/phase-02.html) |
| 03 | Design system, Storybook and theming | Spike S9, then build token-driven UI primitives with per-destination themes, stories, and accessibility checks that every later phase reuses. | Storybook runs in both runtimes or the fallback is recorded as a decision, and no primitive hardcodes destination branding | [03](../planning/phases/phase-03.html) |
| 04 | GitHub previews, native builds and artifact pipeline | Ship 04a (fast web gate plus PR previews with provenance) and 04b (path-filtered, budget-capped Expo native builds) so every meaningful change is remotely inspectable. | 04a is required (PR web preview plus fast gate, no secrets in bundle, provenance recorded); 04b completes when one native build per platform succeeds within the recorded budget ceiling | [04](../planning/phases/phase-04.html) |
| 05 | Tests, regression traps and security guardrails | Teach CI to catch the failure classes the legacy app actually had — async-state spinners, timezone rollover, validity windows, hidden type debt, secret leaks — with red/green proof and a flaky-test protocol. | The fast gate fails correctly on each planted failure class and an agent can diagnose any failure from saved evidence without re-running locally | [05](../planning/phases/phase-05.html) |
| 06 | Widget contract, compiler and two destination builds | Prove typed widget composition and genuine build-time exclusion with two destination web profiles and the flagship union, before any real feature work exists. | Excluded widgets are provably absent from destination web bundles and runtime flags cannot bypass build-time exclusion | [06](../planning/phases/phase-06.html) |
| 07 | Small multi-destination backend and editorial console | Stand up the destination-scoped content API on Cloudflare Workers, D1 and R2 with tenant-isolated editor access, anonymous public reads, provenance, backups and honest failure semantics. | Tenant isolation, backup and restore drills and unavailability tests pass with no public visitor login anywhere | [07](../planning/phases/phase-07.html) |
| 08 | First production-grade widget verticals | Ship the first real end-to-end visitor journeys - places with map, boat transport, tides and weather, local services, and the Serra trails demo - each with truthful offline, error and freshness behavior. | Every widget vertical has docs, stories, tests and provenance evidence on web and Android, with truthful empty, error, offline and stale states - no infinite spinners | [08](../planning/phases/phase-08.html) |
| 09 | Selective migration, field pilot and content operations | Bring verified, consented Cotijuba content into a staging destination through an owner-run export, run the editorial routine for real, and pilot with people on the island. | Verified content with recorded rights serves anonymous visitors in staging, pilot users complete the core journeys, and no anonymous-access or tenancy regression exists | [09](../planning/phases/phase-09.html) |
| 10 | Release discipline, self-service growth and agent continuity | Operationalize launch and rollback, monitoring and budgets, store compliance, and the runbooks and handoff test that let agents keep developing the platform without a growing team. | A rehearsed release and rollback, alerting that fires on real failures, and a different agent shipping a small widget from spec to a green PR unaided | [10](../planning/phases/phase-10.html) |
